1. Contexto e requisitos

Quando a última vaga de um show é vendida, a bilheteria precisa fechar a venda pelo valor correto, atualizar a lotação e confirmar a compra. O atendente acompanha o caixa. O produtor usa o saldo de lugares para orientar o público.

O protótipo acompanha o show fictício Aurora, com duas vagas e ingresso-base de R$ 100,00. Uma segunda apresentação, Horizonte, permite comparar disponibilidades. A simulação ocorre em memória, em um único atendimento por vez.

RegraComportamento verificável
R1Iniciar o show com capacidade inteira positiva.
R2Cobrar o preço-base na inteira e metade na meia, arredondando frações de centavo para cima.
R3Ocupar uma vaga por venda concluída.
R4Recusar venda após a lotação, preservando receita e vagas.
R5Somar a receita de ingressos em centavos.
R6Consultar shows por disponibilidade e gênero.
R7Emitir uma confirmação por venda concluída.

Uma venda muda o estado do show. A soma de preços pode ser recalculada usando apenas a lista de ingressos. Já a pergunta “qual show de rock tem vaga?” depende de relações entre fatos.

3. Venda e controle da lotação

Em modelo.js, vender() calcula o preço, reserva uma vaga e só então altera o caixa. Se reservar() lançar um erro, a venda termina antes da soma e do aviso.

class Bilheteria extends EventTarget {
  #receita = 0;
  vender(show, ingresso) {
    const valor = ingresso.preco();
    show.reservar();
    this.#receita += valor;
    this.dispatchEvent(new CustomEvent("venda", { detail: { show: show.nome, valor } }));
  }
  receita() { return this.#receita; }
}

4. Cálculo funcional da receita

Em funcional.js, a entrada é uma lista de registros de inteira ou meia. map transforma cada registro em preço e reduce soma os valores a partir de zero. As duas funções anônimas são passadas como argumentos.

// Cada linha contém um tipo e um preço-base em centavos.
function totalEmCentavos(linhas) {
  return linhas
    .map(({ tipo, base }) => tipo === "meia" ? Math.round(base / 2) : base)
    .reduce((total, valor) => total + valor, 0);
}
Entrada (tipo e base em centavos)Saída verificada
Inteira de 10000 e meia de 1000015000
Lista vazia0
Meia de 10151

Na bilheteria, o total depende das vendas anteriores. Nesta versão, a lista inteira define o resultado. A função é pura para o domínio de entradas descrito e pode processar novamente os mesmos dados sem duplicar a receita. O teste congela a lista principal e seus registros.

5. Base de conhecimento em Prolog

Oito fatos descrevem dois shows. Os dados de Aurora correspondem ao fim da simulação. Horizonte tem cinco lugares e um ingresso vendido. A base é um retrato estático do cenário.

% Retrato da bilheteria ao final da demonstração.
capacidade(aurora, 2).
capacidade(horizonte, 5).
vendidos(aurora, 2).
vendidos(horizonte, 1).
genero(aurora, rock).
genero(horizonte, pop).
cidade(aurora, ponta_grossa).
cidade(horizonte, castro).

vagas(Show, N) :-
    capacidade(Show, C), vendidos(Show, V), N is C - V.
disponivel(Show) :- vagas(Show, N), N > 0.
esgotado(Show) :- vagas(Show, 0).
opcao(Genero, Show) :- genero(Show, Genero), disponivel(Show).

6. Confirmação por evento

A confirmação acontece depois que a reserva e a soma no caixa terminam. A bilheteria publica o evento venda com o nome do show e o valor pago. O código abaixo registra quem responde ao evento.

let avisos = 0;
caixa.addEventListener("venda", ({ detail }) => {
  avisos++;
  linha("Confirmação " + avisos + " | " + detail.show + " | " + detail.valor + " centavos");
});

Sequência observada

Confirmação 1 | Aurora | 10000 centavos
Confirmação 2 | Aurora | 5000 centavos
Terceira venda: Show esgotado

A terceira tentativa falha antes de dispatchEvent. Por isso há duas confirmações. No navegador, esse evento local é entregue aos ouvintes durante a chamada. Outra função poderia ouvir o mesmo evento para atualizar um painel de ocupação.

Em uma bilheteria comercial, objetos podem organizar o serviço de venda, funções podem calcular o fechamento, regras podem alimentar a busca e eventos podem acionar a emissão de comprovantes. Vendas simultâneas exigiriam persistência e controle transacional.

8. Conclusão e referências

Existe um paradigma melhor para todos os problemas? A escolha depende da operação. O bloqueio da terceira venda mostra a utilidade de concentrar o estado em um objeto. Para conferir os mesmos R$ 150,00, uma função sobre a lista torna explícitos os valores usados. Prolog permite perguntar quais shows ainda atendem a um critério. O evento liga uma venda concluída à confirmação que o atendente vê.

O protótipo também revela um custo de manutenção. A política de meia-entrada aparece nas versões OO e funcional. Se o desconto mudar, os dois cálculos precisam de revisão. A comparação dos resultados com as mesmas entradas ajuda a detectar divergências.
